## Finding

**P2 — An early post-creation failure can leave an unreported incomplete directory; residual errors omit its identity.** `prototype.swift:70–75` creates and opens the incomplete directory, but its first `info(directory)` is outside the cleanup `do/catch` beginning at line 78. If that fstat fails, the descriptor closes and the directory remains, while the caller receives an ordinary `system` error rather than `cleanupIncomplete`. The open failure at line 73 and cleanup failures at line 126 do return `cleanupIncomplete`, but `Failure.cleanupIncomplete` (line 8) carries neither the generated incomplete name nor an operation identifier. The successful target name is different from the random incomplete name, so the caller cannot identify the residual from the error. This falls short of U's explicit residual reporting/reconciliation contract and is not described specifically by README lines 39–41. Fault injection being absent explains missing test coverage, not this control-flow behavior. Keep uncertain state rather than deleting without identity; report the residual name/operation on every failure after mkdir, including inability to establish its identity. Alternatively, clearly label this residual-reporting behavior as unimplemented research scope rather than fulfilled cleanup semantics. No hostile race is needed to observe the error-path issue.

## Verified by inspection

- The gate requires exactly three nonempty contents, declared/actual equality, per-role caps, a checked aggregate and whole-fixture success before explicitly copying contents (`prototype.swift:38–55`). This is a synthetic final-gate model, not archive authentication, bounded inflation or a parser test. Positional roles are fixed; no archive-derived name crosses staging.
- Owned copying uses `Data(bytes:count:)` inside a bounded buffer view. The prototype's `Data(referencing:)` test does not first assert that its bridge actually aliases mutable storage, so that test alone cannot prove alias detachment. The separate memory semantics test does assert visibility through an explicit `bytesNoCopy` view before checking the owned snapshot (`memory.swift:51–61`). Neither test establishes mapped-storage coverage or snapshot-before-real-authentication integration.
- Readback now uses one buffer of at most 65,536 bytes and incremental SHA256 (`prototype.swift:99–114`), not a payload-sized readback copy. Both write and read loops handle EINTR/short progress and poll cancellation per bounded chunk. The tiny prototype fixtures do not exercise a multi-chunk transfer or injected I/O errors. Recorded PASS is parent-provided evidence, not an independently repeated run.
- Creation is descriptor-relative, exclusive and no-follow, with initial UID/type/mode/link checks. `RENAME_EXCL` has no replacing or cross-volume fallback. The success path has no throwing post-rename bookkeeping; cancellation arriving through the post-publication test hook returns success. Collision tests check original directory inode and binary bytes and that no incomplete directory remains. Cleanup scans for unknown children before unlinking known leaves, checking identities without following links. Concurrent identity races remain outside the stated scope.
- Candidate handoff preserves the complete fixed mock evidence value and synthetic/untrusted classification, plus counts/hashes. It closes descriptors before return, as README line 41 now expressly states. The proposed held-handle API in README line 13 is a future design, not this implementation.
- Arithmetic is correct: A=256 MiB, P=264 MiB; A+P=520 MiB (545,259,520 bytes), A+2P=784 MiB, 2A+P=776 MiB, 2A+2P=1,040 MiB. Evidence, parser/transient buffers and overhead are additional. The 33 MiB modeled fixture maximum and approximately 38.7/26.1 MiB recorded process peaks agree with the JSON. No maximum RSS conclusion follows.
- Memory modes all write raw bounded slices. `cow` retains ordinary shared values; `release` drops the archive reference; `owned` explicitly copies and deliberately mutates pages. Their differences and timing exclusions are accurately labeled. The modeled cap is not an OS-enforced RSS cap. The extra 64 KiB allowance for `chunked` is conservative: that mode does not actually allocate a separate write buffer.
