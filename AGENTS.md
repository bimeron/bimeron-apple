# Working agreements

- Write documentation, code comments, commit messages, issues, pull requests, and all other project content in English.
- Use Conventional Commits for commit messages.
- Local commits are allowed without asking. Include accurate `Co-authored-by` trailers when there is a co-author; never invent an identity. Push only when explicitly requested by the user.
- For substantial changes, define an issue, work on a separate branch, and prepare a pull request after discussing the solution with the user.
- Use CI. Treat documentation, meaningful test coverage, and benchmarks as important. Choose checks that verify real behavior rather than mirror implementation.
- Consult the user on architectural decisions. Present options, a recommendation, and material drawbacks. Challenge weak assumptions and revise recommendations when evidence changes.
- Tell the user when changing reasoning effort would help and name the recommended level. Continue at the current level unless the user changes it.
- Use relevant skills when they improve the work, especially `ponytail` for coding tasks.
- Use the `solarcadence` account for GitHub CLI and GitHub operations.
